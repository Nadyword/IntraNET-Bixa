PASO 1 — COMPILAR EL BACKEND EN WINDOWS
================================================================================

Desde la raíz del proyecto en PowerShell:

  dotnet publish backend/Bixa.Backend/Bixa.Backend.csproj `
    -c Release `
    -r linux-x64 `
    --self-contained false `
    -o ./publish_backend

IMPORTANTE: Antes de subir, copia tu appsettings.json de producción
(ya revisado en el Paso 0) dentro de la carpeta ./publish_backend,
reemplazando el que generó el build.


================================================================================
PASO 2 — SUBIR EL BACKEND AL SERVIDOR
================================================================================

Desde PowerShell en tu máquina Windows:

  # Crear la carpeta en el servidor (si no existe)
  ssh root@comunik2.productosbixa.com "mkdir -p /var/www/bixa-backend"

  # Subir los archivos
  scp -r ./publish_backend/* root@comunik2.productosbixa.com:/var/www/bixa-backend/


================================================================================
PASO 3 — PREPARAR EL SERVIDOR (una sola vez)
================================================================================

Conéctate al servidor:
  ssh root@comunik2.productosbixa.com

Crear carpeta de logs:
  mkdir -p /var/log/bixa-backend
  chmod 755 /var/log/bixa-backend

Dar permisos de ejecución al binario:
  chmod +x /var/www/bixa-backend/Bixa.Backend


================================================================================
PASO 4 — CREAR EL SERVICIO SYSTEMD
================================================================================

En el servidor, crea el archivo del servicio:
  nano /etc/systemd/system/bixa-backend.service

Pega este contenido EXACTO:

  -----------------------------------------------------------------------
  [Unit]
  Description=Bixa Backend API (.NET)
  After=network.target mssql-server.service

  [Service]
  WorkingDirectory=/var/www/bixa-backend
  ExecStart=/usr/bin/dotnet /var/www/bixa-backend/Bixa.Backend.dll
  Restart=always
  RestartSec=10
  KillSignal=SIGINT
  SyslogIdentifier=bixa-backend
  User=root
  Environment=ASPNETCORE_ENVIRONMENT=Production
  Environment=ASPNETCORE_URLS=http://localhost:1509

  [Install]
  WantedBy=multi-user.target
  -----------------------------------------------------------------------

Activar e iniciar el servicio:
  systemctl daemon-reload
  systemctl enable bixa-backend
  systemctl start bixa-backend

Verificar que está corriendo:
  systemctl status bixa-backend

Ver logs en tiempo real:
  journalctl -u bixa-backend -f

PASO 5 — ACTUALIZAR NGINX (proxy al puerto 1509)
================================================================================

Edita el archivo de configuración de nginx para comunik2:
  nano /etc/nginx/sites-available/comunik2.productosbixa.com

Asegúrate de que el bloque del backend apunte al puerto 1509:

  location /api/ {
      proxy_pass         http://127.0.0.1:1509/api/;
      proxy_http_version 1.1;
      proxy_set_header   Upgrade $http_upgrade;
      proxy_set_header   Connection keep-alive;
      proxy_set_header   Host $host;
      proxy_set_header   X-Real-IP $remote_addr;
      proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
      proxy_set_header   X-Forwarded-Proto $scheme;
  }

El bloque completo de nginx ya está en el archivo NGINX_CONFIG.txt de este proyecto.

Aplicar cambios:
  nginx -t && systemctl reload nginx


================================================================================
PASO 6 — VERIFICAR CONEXIÓN FRONTEND ↔ BACKEND
================================================================================

El frontend ya está configurado con:
  VITE_API_URL=https://comunik2.productosbixa.com/api
  (archivo frontend/.env.production)

Flujo de una petición:
  Navegador → https://comunik2.productosbixa.com/api/login/AuthenticateLogin
           → nginx recibe en :443
           → proxy_pass a http://127.0.0.1:1509/api/login/AuthenticateLogin
           → Backend .NET responde
           → nginx devuelve la respuesta al navegador

Pruebas manuales en el servidor:

  # 1. Verificar que el backend escucha en 1509
  ss -tlnp | grep 1509

  # 2. Probar el endpoint de login directamente
  curl -s -X POST http://localhost:1509/api/login/AuthenticateLogin \
    -H "Content-Type: application/json" \
    -d '{"taxId":"test","password":"test"}' | head -c 200

  # 3. Probar a través de nginx (como lo hace el frontend)
  curl -s -X POST https://comunik2.productosbixa.com/api/login/AuthenticateLogin \
    -H "Content-Type: application/json" \
    -d '{"taxId":"test","password":"test"}' | head -c 200

  Si el paso 2 responde pero el paso 3 no, el problema es nginx.
  Si ninguno responde, el problema es el servicio del backend.
