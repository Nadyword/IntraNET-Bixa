==============================================================
 DETALLE DE CAMBIOS - Mapeo SnEmple → Users
 Fecha: 2026-05-06
==============================================================

--------------------------------------------------------------
ARCHIVO MODIFICADO
--------------------------------------------------------------
backend/Bixa.Backend.Services/Mapper/BllMappingProfile.cs

--------------------------------------------------------------
QUÉ SE CAMBIÓ
--------------------------------------------------------------
Se agregó un nuevo mapeo de AutoMapper:

    CreateMap<SnEmple, Users>()
        .ForMember(dest => dest.FirstName,  opt => opt.MapFrom(src => src.Nombres))
        .ForMember(dest => dest.LastName,   opt => opt.MapFrom(src => src.Apellidos))
        .ForMember(dest => dest.Ci,         opt => opt.MapFrom(src => src.Ci))
        + Ignore explícito en todos los demás campos de Users

--------------------------------------------------------------
POR QUÉ SE HIZO
--------------------------------------------------------------
En UserService.cs (línea 67) existe la siguiente llamada:

    userCreate = _mapper.Map(snEmple, userCreate);

Esta llamada usa el overload de AutoMapper que recibe un objeto
destino existente y lo sobreescribe con datos del origen.
Para que funcione, AutoMapper requiere un CreateMap registrado
en la dirección SnEmple → Users.

El perfil BllMappingProfile sólo tenía el sentido inverso
(Users → SnEmple), lo que causaba una excepción de mapeo en
tiempo de ejecución al intentar crear un usuario nuevo.

--------------------------------------------------------------
DECISIONES DE DISEÑO
--------------------------------------------------------------
1. Se mapearon ÚNICAMENTE los tres campos que SnEmple tiene
   en común con Users:
     - SnEmple.Nombres  → Users.FirstName
     - SnEmple.Apellidos → Users.LastName
     - SnEmple.Ci       → Users.Ci

2. Todos los demás campos de Users se marcaron con Ignore()
   de forma explícita. Esto es intencional porque:
   - La entidad Users ya fue parcialmente construida por el
     mapeo previo (UserInsertDTO → Users, línea 66).
   - Campos como IdUserRol, PasswordHash, IsActive, etc.,
     provienen del DTO del formulario, NO del sistema externo.
   - Campos de auditoría (CreatedAt, UpdatedAt, ModifiedById)
     no deben ser modificados por datos de SnEmple.
   - Propiedades de navegación (UserRol, Notification) deben
     mantenerse intactas para no romper el contexto EF Core.

3. Se optó por un CreateMap separado en lugar de usar
   ReverseMap() porque los nombres de los campos difieren
   (Nombres/Apellidos vs FirstName/LastName) y ReverseMap()
   no puede inferir ese cruce automáticamente con ForMember.

--------------------------------------------------------------
FLUJO COMPLETO EN AddAsync (UserService.cs)
--------------------------------------------------------------
1. Línea 66: UserInsertDTO → Users
   Establece: Ci, FirstName, LastName, IdUserRol (del formulario)

2. Línea 67: SnEmple → Users (NUEVO MAPEO)
   Sobreescribe: FirstName, LastName, Ci con datos del sistema
   secundario (Profit). El resto de campos permanece igual.

3. Líneas 68-69: Se asignan manualmente IsActive y PasswordHash
   (no dependen de SnEmple ni del DTO).

--------------------------------------------------------------
IMPACTO Y RIESGOS
--------------------------------------------------------------
- Impacto positivo: Resuelve la excepción de AutoMapper al
  crear un usuario nuevo cuando existe información en SnEmple.
- Sin efecto secundario: El mapeo inverso (Users → SnEmple)
  no fue modificado, por lo que el resto del sistema sigue
  funcionando igual.
- Riesgo bajo: El Ignore() explícito garantiza que ningún
  campo sensible (contraseña, rol, tokens) sea sobreescrito
  accidentalmente con null desde SnEmple.
